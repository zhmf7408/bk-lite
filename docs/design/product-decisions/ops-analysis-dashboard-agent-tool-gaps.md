# 运营分析仪表盘智能搭建：现有工具做不到的事

- 最近更新：2026-10-09
- 范围：WebChat 在运营分析仪表盘页，用现有两个工具完成下面四个场景

## 要完成的场景

1. 帮我搭建一个 CMDB 数据概览的仪表盘。
2. 帮我创建告警数据预览的仪表盘，需要有告警总数、告警趋势图。
3. 帮我去掉当前状态为待响应的告警数这个组件。
4. 帮我新增一个告警总数饼图组件。

第 1、2 句是新建一张盘，可以指定目录（例如 `test`）。第 3、4 句是改当前已打开的仪表盘。

## 现有工具实际能做什么

只有两个工具，都在 `server/apps/opspilot/metis/llm/tools/dashboard/`：

| 工具 | 作用 | 不做的事 |
| --- | --- | --- |
| `search_data_sources` | 按组织检索已入库、可出图的数据源，返回数字 `id` | 不建盘，不查 CMDB 实例或告警记录 |
| `prepare_dashboard_proposal` | 校验 `schemaVersion: "1.0"` 的 `layout[].valueConfig` | 不创建仪表盘记录，不写目录，不保存 |

校验通过时只返回页面动作 `dashboard_config_apply`，`dashboardId` 为 `current`。含义是把布局套到当前打开的那张盘上。工具没有目录参数。

页面上有 `readDashboardApplyAction` 和 `applyDashboardProposal`，但仪表盘页和 WebChat 都没有调用它们。工具结果停在对话里。后台仪表盘 `create` 接口存在，没有暴露成工具。

因此模型说「建好了」时，库里不会多出一张盘，刷新目录也看不到。

## 按场景缺的能力

### 1. 新建仪表盘并挂到目录

四个场景里，第 1、2 句以及「建在 test 目录下」都依赖这一条。

缺：

- 按目录名解析目录 id。目录不存在或重名时要能说明，不能假装已建好。
- 创建仪表盘：名称、目录、组织、空布局或已校验方案。
- 创建后把方案写入该盘并保存，返回新盘 id 和名称，让回复能指出它在哪个目录。

现有 `prepare_dashboard_proposal` 不能代替创建。`current` 只表示当前画布，不表示新建，也不表示 `test` 目录。

### 2. 用检索到的数据源拼出指定组件

第 2 句要「告警总数」和「告警趋势图」。第 1 句要 CMDB 概览。第 4 句要告警总数饼图。

数据源目录里已经有对应定义，初始化成功后可检索：

| 说法 | 数据源 | 图表 |
| --- | --- | --- |
| CMDB 数据概览 | `cmdb/get_cmdb_statistics`（CMDB 覆盖概览） | 单值或仪表；分类总数、模型总数、实例总数 |
| 告警总数 | `alert/get_alert_snapshot_statistics` 的 `active_count` | 单值。这是未分派、待响应、处理中的合计 |
| 告警趋势图 | `alert/get_alert_trend_data` | 折线或柱状 |
| 告警总数饼图 | `alert/get_alert_status_distribution` | 饼图，字段是状态名和数量 |

缺的不是再造 CMDB 实例或告警工单。缺的是：新建或改盘时，方案必须使用上述数字 id，并且图表类型必须落在该数据源声明的 `chart_type` 里。快照数据源只有单值，不能当成饼图。

### 3. 改当前盘：删除组件、新增组件

第 3、4 句是改当前布局，不是新建。

缺：

- WebChat 工具结果要交给当前仪表盘页。编辑页已经会把布局放进页面上下文，但 `dashboard_config_apply` 没有被页面执行。
- 套上布局之后要保存。只改内存，刷新就没了。
- 删除必须针对当前布局里真实存在的组件。内置「统一告警中心仪表盘」没有单独的「待响应告警数」组件；该单值在「告警运营大屏」上，字段是快照数据源的 `pending_count`。当前盘没有这个组件时，应说明删不到，而不是回复已去掉。

## 建议补上的工具能力

保持「检索」和「校验方案」两个工具。再补持久化，不要让模型以为 `pageAction` 已经落库。

1. 解析目录：按名称在当前组织下找目录，返回 id。
2. 创建仪表盘：名称、目录 id、已校验方案，写入并返回新盘 id。
3. 保存当前盘：仅当页面上下文里有当前仪表盘 id 和布局时，把校验后的方案保存到这张盘。删除、新增组件走这一条。
4. 页面执行并保存：WebChat 收到 `dashboard_config_apply` 后，应用到对应盘并调用保存。没有这一步，工具返回成功用户仍然看不到。

第 1、2 句走「解析目录（可选）→ 检索数据源 → 校验方案 → 创建并保存」。第 3、4 句走「读当前布局 → 检索数据源（新增时）→ 校验方案 → 保存当前盘」。
